### ⚖️ LegalTech RAG for UK Statutes
> Source-grounded legal question answering over **48,000+ UK statutory documents** with citation-ready answers.

- 🔍 Benchmarked **4 retrieval strategies**: BM25 · dense embeddings (`all-MiniLM-L6-v2`) · **hybrid via Reciprocal Rank Fusion** · **neural reranking** (`cross-encoder/ms-marco-MiniLM-L6-v2`)
- 🧩 **Structure-aware chunking** preserving legal context, section identifiers & citation metadata
- ⚙️ **Function-calling orchestration with FunctionGemma** (270M params) — the model itself decides when to search, retrieve sections, rerank & format citations
- ⚡ **Two-stage pipeline** (fast retrieval → focused reranking) for low latency + refusal logic for out-of-scope queries
- 📏 Eval framework with **Recall@K, Precision@K, nDCG@K** — hybrid + reranking achieved the best ranking quality

![Sentence-Transformers](https://img.shields.io/badge/Sentence--Transformers-FFD21E?style=flat-square&logo=huggingface&logoColor=black) ![FunctionGemma](https://img.shields.io/badge/FunctionGemma-4285F4?style=flat-square&logo=googlegemini&logoColor=white) ![Hybrid Retrieval](https://img.shields.io/badge/Hybrid_Retrieval_•_RRF-6A5ACD?style=flat-square) ![Cross-Encoder Reranking](https://img.shields.io/badge/Cross--Encoder_Reranking-DC143C?style=flat-square)

### 🔗 Multi-Hop Retrieval QA — Improving Evidence Selection for RAG
> LLM-based **multi-hop question answering** on HotpotQA (**100,000+ Wikipedia QA pairs**) requiring synthesis across multiple documents.

- 🧠 **Evidence selection** that ranks & filters candidate passages across reasoning hops — systematically cutting distractors and finding missing links in evidence chains
- 🎯 Solved a key production failure mode: vanilla top-k retrieval breaks on multi-hop questions where second-hop evidence has **no lexical overlap** with the query → fixed with **iterative chained retrieval**
- 📊 Evaluation combining answer accuracy with **supporting-fact overlap**, plus analysis of retrieval failure modes
- ✅ Result: better answers **and** more transparent, auditable reasoning for reliable RAG deployments
